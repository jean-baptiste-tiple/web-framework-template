# Accessibilité

- HTML sémantique : header/nav/main/article/section/footer, un seul h1.
- Charge cognitive : nav top-level ≤ 5 items ; 1 action primaire par écran (+ 1-2 secondaires, le reste en menu) — la mémoire de travail tient ≤ 4 éléments.
- alt sur toutes les images. Liens explicites (pas de "cliquez ici").
- Composants interactifs au clavier. Préférer natif (<details>, <dialog>, <button>).
- Contraste : toute PAIRE de tokens texte/fond utilisée en markup (fg/muted × bg/surface/primary) tient ≥ 4.5:1 — contrôle machine : `pnpm run audit:lh` (audit `color-contrast`), à relancer après tout changement de token couleur. Focus visible conservé.
- **Angle mort de l'audit machine** : `color-contrast` ne juge que ce qui est VISIBLE au chargement. Une paire portée par un élément masqué au départ (`hidden`, `<details>` fermé, état d'erreur d'un formulaire) passe l'audit sans être mesurée. Ces paires-là se calculent à la main (OKLCH → sRGB → ratio WCAG) et vont dans la table de `docs/design/system.md § Contrastes tenus` — contrôlable en review : un élément masqué qui porte une classe de couleur sans ligne dans cette table est une violation.
- Îlots Solid : aria-* corrects, état annoncé.
